# 공공데이터 자동등록 — 내부망 RPA 연결 준비본

**현재 실제 포털 등록 기능은 연결되지 않았습니다.** 이 프로젝트에는 기존 Selenium 원본이 없었습니다. 사전검사만으로 등록 성공이라고 표시하지 않으며, 홈페이지도 PC 프로그램을 실행하지 않습니다.

## 내부망 PC로 가져갈 구조

이 `internal-rpa` 폴더를 내부망 PC의 승인된 위치에 `공공데이터_자동등록` 등의 이름으로 복사할 수 있습니다. 기존 RPA의 고정 작업 폴더가 있으면 기존 경로를 우선하고, 아래 프로그램의 파일 선택창 또는 인자로 지정하세요. 절대 경로를 코드에 고정하지 않습니다.

```text
공공데이터_자동등록/
├─ 실행/포털자동등록.bat
├─ preflight.py                 # 사전검사와 연결 모듈 호출
├─ rpa_adapter.py               # 기존 RPA 연결 진입점, 현재 CONFIGURED=False
├─ 분류체계.json                 # 홈페이지와 같은 확인 전사 목록, 공식 코드값은 미확인
├─ 등록자료/                     # 다운로드한 등록자료.xlsx와 원본 CSV를 사용자가 배치
└─ 실행결과/                     # 연결 RPA 실행 결과를 내부망 PC에만 저장
```

Python3(권장3.10 이상)가 필요합니다. 사전검사에는 pip/추가 패키지/인터넷/AI API가 필요 없습니다. Python과 원래 RPA의 Selenium·브라우저·드라이버 환경은 내부망 PC의 기존 설치 절차를 따릅니다. 이번 노트북에서 내부망 설치나 드라이버 호환을 확인하지 않았습니다.

## 담당자가 사용할 순서

1. 내부망 PC에서 공개 AI 홈페이지 접속이 가능한지 확인하고 입장합니다. 현재 변경은 배포 전이므로 승인·배포 후 새 화면을 사용합니다.
2. CSV를 선택해 AI 등록정보를 생성하고 필요한 값을 수정합니다. 원본 행·셀은 외부 AI에 전송하지 않지만 파일명·컬럼명 등 구조정보는 전송되는 기존 방식입니다.
3. `등록자료.xlsx`를 다운로드합니다. 다운로드 번호가 붙은 이름은 이 작업 폴더에서 `등록자료.xlsx`로 확인해 주세요. 기존 파일을 덮어쓸지는 담당자가 판단합니다. 프로그램은 자동 덮어쓰지 않습니다.
4. 등록할 원본 CSV와 Excel을 기존 RPA 지정 폴더에 둡니다. CSV 이름은 Excel C열 데이터명에 `.csv`를 붙인 이름과 정확히 같아야 합니다. V열에 기존파일명이 있으면 그것도 일치해야 합니다. Excel과 원본 CSV를 자동 변경하지 않습니다.
5. `실행/포털자동등록.bat`를 실행하고 Excel과 CSV 폴더를 선택합니다. 잘못된 파일·누락 CSV가 있으면 시작하지 않습니다.
6. **현재 준비본은 기존 RPA 미연결로 종료됩니다.** 원본 연결·검증 후에만 실제 등록을 사용할 수 있습니다.
7. 연결 후에는 검사 결과를 보고 `등록시작`을 직접 입력해야 실제 실행합니다. 취소할 수 있으며 홈페이지 버튼은 이 확인을 대신하지 않습니다.
8. 내부망 포털 화면과 실행결과 JSON으로 실제 등록 결과를 확인합니다. 외부 홈페이지에 자동 결과 동기화는 하지 않습니다.

## 사전검사만 실행

```powershell
py -3 .\preflight.py --excel ".\등록자료\등록자료.xlsx" --csv-dir ".\등록자료"
```

파일 선택창은 `--interactive`, 기존 RPA 연결 후 실행 확인까지는 `--interactive --run`을 사용합니다. `py` 대신 설치된 `python` 명령도 사용할 수 있습니다. 작업 폴더가 다르면 해당 경로를 인자로 선택하세요. `--adapter`/`--output-dir`로 연결 모듈과 결과 위치를 바꿀 수 있습니다.

검사 내용: 등록대장 시트, 정확한 A~W23개 헤더·순서,1~10건/2~11행, B미등록,C/D/H/I/J 필수값, 실제 분류 조합, 중복 데이터명, 안전한 파일명, C/V 일치, 대응 CSV 존재·비어 있지 않음입니다. 이미 등록된 행/검토용 Excel/수식/손상·암호 Excel은 차단합니다. 행 사이 빈 행도 제거해야 합니다. 원본 CSV 내용의 업무 정확성·포털 중복 등록 여부는 이 도구가 판단하지 않습니다.

법률명 미검증과 법적 업무 적합성은 별개입니다. Excel 보유근거는 존재해야 하지만 이 도구가 법률의 적법성을 확정하지 않습니다. 분류 목록의 공식 코드값·향후 변경도 확인된 것이 아닙니다.

## 개발 담당자의 기존 RPA 연결 작업

아래 사항을 확인한 후 `rpa_adapter.py`만 연결합니다. 임의 선택자로 새 등록기를 만들지 않습니다.

- 기존 Selenium 원본·실행 명령·의존성·브라우저/드라이버 버전
- 기존 Excel/CSV 작업 경로 및 B열 상태 처리 방식
- 현재 포털의 실제 등록 화면/인증 절차/성공 확인 지점
- 기존 결과 기록 방식과 실패 후 재실행·중복 등록 방지 방식

`CONFIGURED=True`는 연결 작업을 마치고 테스트한 후에만 설정합니다. `register_records(excel_path,csv_dir,records,report_result,report_started)`는 지정한 Excel/CSV 폴더와 원래 Excel 행 번호를 받습니다. 기존 RPA가 여러 행을 직접 읽는 방식이면 그 방식을 재사용하세요. 기존 프로그램이 경로 변경이나 상태 기록을 요구하면 원본 계약을 확인한 뒤 연결해야 합니다.

- 개별 처리 시작: `report_started(row)`
- 실제 포털 성공 화면을 확인한 후에만: `report_result(row, True, portal_confirmed=True)`
- 실패: `report_result(row, False, 'PORTAL_REJECTED')` 등의 고정 코드
- 결과 미확인: 성공으로 보고하지 않습니다. 확인 플래그 없는 성공 요청은 미확인으로 기록합니다.

허용 실패 코드는 `PORTAL_REJECTED`, `AUTH_REQUIRED`, `PORTAL_LAYOUT_CHANGED`, `RPA_ERROR`, `PORTAL_RESULT_NOT_CONFIRMED`, `NOT_PROCESSED`입니다. 임의 예외문·URL·비밀번호·쿠키·CSV 내용·개인정보를 전달하거나 출력하지 마세요. 입력 파일명·데이터명에도 개인정보가 없는지 담당자가 확인해야 합니다. 연결 모듈의 stdout/stderr는 실행기에서 출력하지 않고, 결과는 데이터명/시각/성공 여부/고정 사유 코드만 로컬 JSON에 기록합니다. 개별 시작 시각을 보고하지 않은 항목은 null로 남습니다.

실행 전 확인 전에 연결 모듈을 import하지 않습니다. 확인 후 입력을 다시 검사하며, 목록이 바뀌거나 CSV가 사라지면 실행하지 않습니다. 실행 중 파일을 수정하지 마세요. 기존 RPA의 동작 자체는 원본 연결 후 별도 검증해야 합니다.

## 결과·종료 코드

- 0: 사전검사 통과만 했거나, 연결 모듈이 모든 대상의 실제 포털 성공 확인을 보고함. 출력 문구/결과 파일의 phase로 구분합니다.
- 2: 입력 검사 실패 / 3: RPA 미연결 / 4: 사용자 취소 / 5: 실행 실패·미확인 포함

결과 JSON의 `preflight_passed`는 등록 성공이 아닙니다. 각 행 `success`가 true인 경우에만 연결한 RPA가 포털 결과 확인을 보고했다는 의미입니다. 이번 준비본에는 실제 포털에 접속하는 코드가 없습니다.

입력·실행결과 폴더의 실제 파일은 Git 제외이며 공개 Worker 자산에도 포함되지 않습니다. 이 준비본을 배포하더라도 내부 자료를 외부에 올리는 용도로 사용하지 마세요.

## 참조 목록 갱신·테스트

외부망 개발 프로젝트에서 `node prepare-rpa-reference.mjs`를 실행하면 기존 분류체계DB를 읽어 이 폴더의 참조 JSON만 다시 만듭니다. 원본 DB는 변경하지 않습니다. 업데이트된 참조를 내부망에 옮기는 방법은 기관 파일 반입 절차를 따릅니다.

`python test_preflight.py`는 임시 합성 파일과 모의 adapter만 사용합니다. 포털에는 접속하지 않습니다. 실제1/5/10건 등록은 원본 RPA 연결 후 내부망에서 별도로 확인해야 합니다.
